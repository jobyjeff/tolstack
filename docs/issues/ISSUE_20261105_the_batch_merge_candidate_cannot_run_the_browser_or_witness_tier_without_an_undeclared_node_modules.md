# The batch-merge candidate cannot run the browser TRUTH or mutation-witness tier without an undeclared `node_modules`

dispatch's triage batch-merge duty (`dispatch/dispatch/prompts/TRIAGE_AGENT.md`,
step 2) runs every tier on the **merge candidate**, a throwaway worktree at
`<integration> + merge <trunk>`. tolstack's `CLAUDE.md` names four extra tiers a
batch merge runs, and two of them import `playwright-core`:
`node scripts/run_viewer_browser_tests.mjs` and
`node scripts/run_mutation_witness_tests.mjs --changed-since master` (when it
selects a browser entry). `node_modules` is gitignored and is not in
`.dispatch.toml`'s `[tests] candidate_inputs`, so `bridge-test-inputs` does not
link it.

Measured 2026-11-05 on the candidate (`b58f8ed2`):

```
node scripts/run_viewer_browser_tests.mjs
  -> ERR_MODULE_NOT_FOUND (playwright-core), exit 1
```

That red is an invented one (step zero: unproven, not failing). It was disproved
by `dispatch.cli bridge-test-inputs ... --also node_modules`. After that the browser
tier ran 40/41 (one known load flake, filed separately) and the witness tier ran
4/4 witnessed.

## The conflict to settle

`CLAUDE.md` (Environment, the candidate-inputs bullet) says `node_modules` is
**deliberately** not declared, because "the browser TRUTH tier it would arm
already runs separately in the main checkout at merge time". Before the merge, the
main checkout is on trunk, so a run there tests trunk and not the candidate. After
the merge, the run is too late to gate anything. The dispatch prompt and this
repo's `CLAUDE.md` give different answers, and each sweep re-derives the `--also`
disproof.

## To do

Pick one and make the other text agree:

- declare `node_modules` in `[tests] candidate_inputs` (it is read-only to both
  runners as far as this sweep could tell; confirm with a before/after manifest
  diff, the same way the other six paths were confirmed), and drop the "deliberately
  not declared" sentence; or
- keep it undeclared and change the `CLAUDE.md` bullet so it says how a batch
  merge gates those two tiers on the candidate. A dispatch-side note would then
  belong in the triage prompt (dispatch's call, not this repo's).
